# План: Перевод транскриптов на украинский (и другие языки)

## Цель

Добавить функцию перевода предложений транскрипта с исходного языка на выбранный пользователем (по умолчанию украинский) с отображением в dvojном стовпці (оригинал | перевод). Колонка перевода скрывается/показывается по клику. Состояние запоминается в localStorage.

## Зависимости

- Использовать существующий `httpx` (уже в requirements.txt) для вызова Groq Chat API
- Новые зависимости не требуются
- `groq_chat_model` уже есть в `app/config.py` (строки 30)

## Загаданные файлы для изменения

1. `app/config.py` — добавить настройки:
   - `translation_enabled: bool = True`
   - `translation_target_languages: list[str] = ["uk", "pt-PT", "es", "en"]`
   - `translation_default_language: str = "uk"`
   - `translation_batch_size: int = 10` (предложений на запрос)

2. `app/services/formatter.py` — добавить функцию перевода:
   - `async def translate_sentences(sentences: list[str], target_lang: str, api_key: str | None) -> list[str]`
   - Вызов Groq Chat API с промптом для перевода на целевой язык
   - Возврат списка переводов в том же порядке

3. `app/services/storage/archive.py` — добавить `formatted-<lang>.txt` в ARTIFACTS для архивации в Telegram

4. `app/routers/translations.py` — новый роутер:
   - `GET /api/translate/{recording_id}` — вернуть перевод (из кэша или перевести)
   - `DELETE /api/translate/{recording_id}` — сбросить кэш перевода (повторный перевод)

5. `app/routers/pages.py` — передать `translation_enabled` и `translation_languages` в шаблон

6. `templates/transcript.html` — двойной столбец, кнопка показа/скрытия перевода, подсветка соответствия

7. `static/js/app.js` или новый `static/js/translation.js` — клик по кнопке, localStorage, подсветка

8. `tests/` — unit-тесты для функции перевода (с моком Groq)

9. `AGENTS.md` — добавить раздел о переводе

10. `README.md` — опционально, раздел о переводе

## Datenfluss

1. Пользователь открывает `/t/{recording_id}`
2. Страница запрашивает `GET /api/translate/{recording_id}?lang=uk`
3. Роут проверяет кэш `formatted-uk.txt` — если есть, возвращает перевод
4. Если кэша нет — читает `formatted.txt`, разбивает на предложения, отправляет пакетами в Groq Chat API
5. Перевод сохраняется в `formatted-uk.txt`, возвращается клиенту
6. Клиент отображает двойной столбец, состояние скрытия в localStorage

## Failure modes

- Groq API недоступен → показать ошибку пользователю, только оригинал
- Ключ невалиден → ошибка 401, пользователь должен войти заново
- Файл formatted.txt отсутствует → ошибка 404 (транскрипт не готов)
- Кэш файла поврежден → пересоздать при следующем запросе

## Validation

1. `pytest` — все существующие тесты проходят
2. Новые тесты в `tests/test_translation.py` — перевод с моком Groq
3. Ручная проверка в браузере: открыть транскрипт, включить перевод, скрыть/показать колонку, проверить localStorage
4. Проверить архитекру TTS-записи (kind=tts) тоже получают перевод
