?# ТЗ: Озвучка текстового файла (TTS)

> Функция: пользователь загружает текстовый файл (.txt / .md) и получает готовую аудиозапись (MP3), озвученную через TTS-провайдера. Результат появляется в общем списке записей и воспроизводится в существующем плеере.

## 1. Цель

Расширить сервис «в обе стороны»: сейчас первоисточник — аудио (аудио → транскрипт), добавить обратный поток (текст → аудио). При этом максимально переиспользовать существующую инфраструктуру: карточки записей, плеер с подсветкой предложений, Telegram-архив, retention, статусы.

## 2. Ключевое проектное решение: TTS-провайдер

**Решение (утверждено):** провайдер по умолчанию — **edge-tts** (голоса Microsoft: бесплатно, MP3 на выходе). Платные TTS-провайдеры (**OpenAI**, **Grok / xAI**) подключаются опционально через конфиг (`TTS_PROVIDER` + серверный ключ). Слой `TTSProvider` делается по образцу `transcriber.py`: единый интерфейс `synthesize(text, voice) -> (audio_bytes, format)`, реализации `edge`, `openai`, `grok`. Mock-режим обязателен для тестов без сети.

**Основные языки озвучки:** английский (по умолчанию), европейский португальский (`pt-PT`), испанский (`es`), украинский (`uk`). Никакой привязки к русскому нет — список языков задаётся кураторским списком голосов и легко расширяется (у edge-tts — сотни голосов на всех перечисленных языках).


Особенности платных провайдеров:
- **OpenAI** (`gpt-4o-mini-tts` / `tts-1`): ~$15/1 млн символов, все основные языки (en, pt, es, uk и десятки других), знакомый REST-интерфейс; ключ серверный (`OPENAI_API_KEY`).
- **Grok (xAI)** (`POST https://api.x.ai/v1/tts`): $15/1 млн символов, язык передаётся BCP-47 (`en`, `pt-PT`, `es-ES`, `uk`) или `auto`-детект, 5 встроенных голосов (`eve`, `ara`, `rex`, `sal`, `leo`), на выходе MP3 (по умолчанию 24 kHz/128 kbps, настраивается), до 60 000 символов на запрос, inline-теги `[pause]`/`[laugh]`; ключ серверный (`XAI_API_KEY`).


Особенности edge-tts:
- библиотека `edge-tts` (pip), работает напрямую с голосами Microsoft Edge (нужен только интернет, ключ не нужен);
- основные языки: английский `en-US-GuyNeural`, `en-US-JennyNeural` (дефолт), `en-GB-RyanNeural`; португальский `pt-PT-DuarteNeural`, `pt-PT-RaquelNeural`; испанский `es-ES-AlvaroNeural`, `es-ES-ElviraNeural`; украинский `uk-UA-OstapNeural`, `uk-UA-PolinaNeural` — всего сотни голосов, полный список через `edge_tts.list_voices()`;
- формат вывода — MP3 (24 kHz) → склейка через ffmpeg без промежуточных WAV;
- жесткого лимита длины запроса нет (библиотека шлёт текст порциями сама), но для прогресса и таймингов текст всё равно режется по предложениям (`TTS_CHUNK_CHARS`);
- официальных квот нет, но это неофициальный протокол — см. риски §11.

**Резервные недорогие варианты (вне MVP, при желании добавить в `TTSProvider` позже):**
- **Azure AI Speech** — ~$14/1 млн символов, бесплатные 500 тыс. символов/мес постоянно, 140+ языков (en, pt-PT, es, uk — все есть), официальный стабильный API — фактически «платная замена edge-tts» без риска неофициального протокола;
- **Google Cloud Text-to-Speech** — ~$16/1 млн символов, бесплатные 1 млн символов/мес на WaveNet/Neural2, все основные языки поддерживаются, официальный API.


## 3. Архитектура: TTS-задача как `Recording`

TTS-задача моделируется **той же сущностью `Recording`**, с типом-признаком. Это бесплатно даёт: список карточек, страницу плеера, статусы, удаление, Telegram-архив, retention.

Новые файлы в папке записи (`data/<user_id>/<recording_id>/`):

```
text.txt          # исходный текст (переименованный original.tmp)
chunks/tts-N.wav  # промежуточные WAV-фрагменты (удаляются после склейки)
audio.mp3         # итоговый MP3 48 kbps mono — как у обычных записей
transcript.json   # синтетический транскрипт: сегменты = TTS-чанки с таймингами
formatted.txt     # = исходный текст (для кнопки «Скачать TXT»)
```

`transcript.json` строится так: после каждого синтезированного WAV берётся его длительность (`ffprobe`), сегменты получают кумулятивные `start`/`end`. Плеер с подсветкой предложений работает **без изменений**.

Изменения в `app/models.py`:
- `Recording.kind: str` — `"transcription"` (дефолт колонки, чтобы старые записи не трогать) / `"tts"`. Миграция — additive, её уже умеет делать `_add_missing_columns` в `database.py`.
- `Recording.tts_model: str | None`, `Recording.tts_voice: str | None` — чем озвучено (для перегенерации и UI-бейджа).

## 4. Поток обработки (pipeline)

Новый модуль `app/services/tts.py` (провайдеры и чанкинг) и `process_tts()` в `app/services/processing.py`.

1. `POST /api/tts/upload` (`.txt`, `.md`; лимиты `TTS_MAX_FILE_MB` и `TTS_MAX_CHARS` символов).
2. Файл сохраняется как `original.tmp`, создаётся `Recording` (`kind="tts"`, `status="pending"`) — по образцу `routers/upload.py`.
3. Фоновая задача `process_tts(recording_id)`:
   - чтение и нормализация текста: склейка переносов строк, схлопывание пробелов; `status="processing"`;
   - разбиение на чанки по предложениям: ≤ `TTS_CHUNK_CHARS` (дефолт ~1000; у Grok лимит запроса 60 000 симв. — не достигается, у OpenAI запрос ~4096 симв. — тоже); абзацы — приоритетная точка разреза;
   - для каждого чанка (пул из `TTS_CONCURRENCY` задач, дефолт 2–4; лимиты запросов платных провайдеров уважаются паузой `TTS_REQUEST_INTERVAL`): синтез → сохранение `chunks/tts-N.mp3` (или `.wav` — формат провайдера), `ffprobe` длительности;
   - ретраи: HTTP/сетевые ошибки → ограниченное число повторов с паузой; 429 у платных провайдеров → пауза по `retry-after`; 401/403 → `TTSAuthError` (см. §7);
   - склейка через ffmpeg (по образцу `converter.split_audio`) в единый MP3 48 kbps mono → `audio.mp3`;
   - запись `transcript.json` (сегменты = чанки с кумулятивными таймингами) и `formatted.txt`;
   - удаление `chunks/`, `original.tmp`;
   - `status="done"` → обычный `_archive_to_telegram()` — архивирование переиспользуется без правок.
4. Прогресс для длинных текстов отдаётся в status-эндпоинте (§6).

Зависимость: `edge-tts` добавляется в `requirements.txt` (лёгкая, только websockets/httpx — других новых зависимостей не нужно).

## 5. Конфигурация (`app/config.py`, `.env.example`)

```
TTS_ENABLED=true                  # показать ли вкладку/зону загрузки текста
# Активный TTS-провайдер: edge (бесплатно, по умолчанию) | openai | grok
TTS_PROVIDER=edge
# Голос по умолчанию в формате "<провайдер>:<голос>" (каждый провайдер берёт своё имя голоса)
TTS_VOICE=edge:en-US-GuyNeural
TTS_CHUNK_CHARS=1000              # символы на один чанк
TTS_CONCURRENCY=3                 # одновременных запросов
TTS_MAX_CHARS=200000              # суммарный лимит на файл
TTS_MAX_FILE_MB=2                 # лимит размера .txt/.md
TTS_MAX_RETRIES=3
TTS_REQUEST_INTERVAL=0            # пауза между запросами (поднять при упоре в RPM платного провайдера)
# Ключи платных провайдеров — серверные; активны, только когда TTS_PROVIDER указывает на них.
OPENAI_API_KEY=                   # только если TTS_PROVIDER=openai
XAI_API_KEY=                      # только если TTS_PROVIDER=grok
```

## 6. API

| Метод/путь | Назначение |
|---|---|
| `POST /api/tts/upload` | Загрузка текстового файла (+ `voice: Form, optional`, `model: Form, optional`). Валидация расширения/размера/числа символов; создание `Recording`; запуск фоновой задачи. Ответ — как у `/api/upload`. |
| `GET /api/recordings/...` | Существующие эндпоинты списка/статуса/плеера — **без изменений**. В `/status` для `kind="tts"` дополнительно: `chunks_done`, `chunks_total` (прогресс). |
| `GET /api/recordings/{id}/audio` | Без изменений: отдаёт `audio.mp3` (FileResponse уже есть). |
| `GET /api/recordings/{id}/download` | TXT-кнопка работает: отдаёт `formatted.txt`. |
| `DELETE /api/recordings/{id}` | Без изменений. |
| `GET /api/tts/voices` | Список голосов активного провайдера для UI: для `edge` — кураторский список по основным языкам (en дефолт, pt-PT, es, uk; при желании полная выборка через `edge_tts.list_voices()`), для платных — статические словари. |

Загрузка текста может быть добавлена и в общий `/api/upload` (расширить `ALLOWED_EXTENSIONS`), но отдельный эндпоинт чище: другая валидация, другая фоновая задача, отдельные лимиты.

## 7. Обработка ошибок

- Отказ ключа платного провайдера (401/403) → `TTSAuthError`: `status="error"`, понятное сообщение пользователю (проверка ключа в админ-настройках).
- 429 → ретрай с `retry-after` (лимит попыток `TTS_MAX_RETRIES`); если квота провайдера на сегодня исчерпана → `status="error"` с сообщением «квота провайдера на сегодня исчерпана».
- Ошибка на чанке N → ретраи, затем `status="error"` с номером чанка в `error_message`; готовые WAV сохраняются в `chunks/` для возможного продолжения (phase 2: «resume с чанка N»).
- Пустой файл / только служебные символы → 400 на загрузке.
- Markdown-разметка вычищается перед озвучкой: заголовки `#`, ссылки `[текст](url)` → «текст»; код-блоки — опция (пропускать или читать как текст).

## 8. UI

- На странице загрузки: та же drag-and-drop зона принимает `.txt`/`.md` (когда `TTS_ENABLED=true`).
- Для TTS: селектор языка, сам голос выбирается рандомно из имеющихся; бейдж «TTS» на карточке.
- Страница плеера (`/t/{id}`) — без изменений: тот же `<audio>` + подсветка по `transcript.json`.

## 9. Тесты (по образцам существующих)

Новый `tests/test_tts.py` + дополнения в `test_processing.py`, `test_routes.py`:

- разбиение текста на чанки: по предложениям, лимит символов, длинное предложение без точек, пустой текст;
- `MOCK_TTS=true`: вместо сетевого запроса генерируется WAV/MP3-тон через `ffmpeg -f lavfi sine` (аналог `mock_transcription`) — полный пайплайн проверяется без сети и ключей;
- выбор провайдера: `TTS_PROVIDER=edge|openai|grok` резолвится в нужную реализацию; формат запроса каждого провайдера мокается на уровне `TTSProvider`;
- склейка: длительность `audio.mp3` ≈ сумме длительностей чанков; `transcript.json` содержит корректные кумулятивные тайминги;
- ретраи 429 (мок httpx), исчерпание квоты провайдера → error-статус;
- 401/403 от платного провайдера → `TTSAuthError` → error-статус с понятным сообщением;
- роуты: 400 на неподдерживаемое расширение, превышение `TTS_MAX_CHARS`, авторизация, прогресс в `/status`;
- удаление TTS-записи чистит файлы и архив (существующие тесты удаления — убедиться, что `kind="tts"` не ломает).

## 10. Этапы работ

1. **Этап 1 — ядро:** `config` + `models` (миграция) + `services/tts.py` (провайдер `edge`, интерфейс для платных провайдеров, mock) + `process_tts` + тесты ядра; `edge-tts` в `requirements.txt`.
2. **Этап 2 — API:** `/api/tts/upload`, `/api/tts/voices`, прогресс в `/status`.
3. **Этап 3 — UI:** приём текстовых файлов, выбор голоса, бейджи, плашка лимитов.
4. **Этап 4 (опционально):** платные провайдеры (`openai` и `grok` — на серверных ключах), резервные провайдеры (Azure Speech, Google Cloud TTS), resume с чанка, вычистка Markdown, кэш по хэшу текста.

## 11. Риски и ограничения

- **edge-tts — неофициальный протокол** (эмуляция клиента Edge Read Aloud): Microsoft может изменить/закрыть эндпоинт без предупреждения. Смягчение: сменный провайдер в конфиге + понятная ошибка в UI при недоступности.
- edge-tts требует прямого доступа из сервера к `speech.platform.bing.com` — учесть в сетевых правилах VPS.
- Платные провайдеры: OpenAI — все основные языки, ~$15/1 млн символов (`gpt-4o-mini-tts` дешевле базового `tts-1`); Grok (xAI) — язык через BCP-47 или auto, $15/1 млн символов, 60 000 симв./запрос, 5 голосов. Оба — на серверных ключах, стоимость относится на владельца сервера.
- Синтетический «транскрипт» совпадает с речью только на уровне чанков — подсветка работает на уровне предложений, не слов; для этого сценария этого достаточно.
